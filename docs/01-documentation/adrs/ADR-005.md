# ADR-005: Lean 4 formal model of CoW extent shadowing and rollback

## Status
Accepted

## Context

Rollback correctness must be mathematically guaranteed: terminating a
malicious process tree and replaying inverse ring-buffer descriptors must
restore bit-exact pre-infection file state, with no orphan inode leakage
and no journal desynchronization.

Constraints:
- Model copy-on-write extent shadowing as a deterministic
  state-transition machine.
- Mechanize a Crash-Consistent Rollback Invariant in Lean 4.
- Prove: restore bit-exact pre-image, no orphan inodes, no journal desync.
- Target: 0 `sorry` in the final Lean development.

Options Considered
1. **TLA+ model checking** — exhaustive state exploration but not a
   machine-checked proof of bit-exactness.
2. **Coq / Isabelle** — powerful but outside the team's Lean 4 expertise
   and toolchain.
3. **Lean 4 deterministic state machine + invariant theorems** —
   machine-checked proof, matches the "0 sorry" requirement; chosen.

## Decision

Model CoW extent shadowing as a deterministic Lean 4 state-transition
machine (`FSState`: clean/dirty/rolling) with a `step` relation, and
mechanize the Crash-Consistent Rollback Invariant proving that process
termination + inverse descriptor replay restores bit-exact state with no
orphan inodes and no journal desync.

## Consequences

### Positive
- Machine-checked guarantee of rollback correctness.
- Explicitly rules out orphan inode leakage and journal desynchronization.
- 0-sorry target provides a clear completion criterion.

### Negative
- Proof effort is high; all theorems currently `sorry` in the skeleton.
- Lean model must stay in sync with the eBPF/Go implementation as it
  evolves.

## Revisit When

The eBPF or Go layer changes the extent-splicing or descriptor format;
the Lean model and proofs must be updated to remain faithful.

# ADR-001: Kernel interception via eBPF on vfs_write and security_file_permission

## Status
Accepted

## Context

Chronos must intercept file writes before the dirty page crosses the VFS
to page-cache boundary so pre-image extents can be captured before
ransomware encryption commits corrupted bytes to disk.

Constraints:
- Linux 6.x, specifically 6.2 kernel.
- Bare-metal Ubuntu 22.04 or fully virtualized VM required; WSL2 eBPF
  support is unstable for deep VFS hooks.
- Two interception points needed: `vfs_write` (VFS write path) and
  `security_file_permission` (pre-permission check).
- Classification must be sub-microsecond so p99 I/O overhead stays under
  1.4% on benign PostgreSQL TPC-C and RocksDB YCSB traffic.

Options Considered
1. **kprobe on vfs_write + security_file_permission** — works on 6.2,
   stable, but slightly higher per-event overhead than fentry/fexit.
2. **fentry/fexit (BPF trampoline)** — preferred on 6.2+ with BTF,
   lower overhead, but requires BTF-enabled kernel and vmlinux.h.
3. **Tracepoints (tracepoint/syscalls/sys_enter_write)** — stable ABI
   but coarser granularity; misses the VFS-internal page-cache boundary
   and the security hook.
4. **LD_PRELOAD / userspace interception** — bypassable, adds context
   switch latency, cannot guarantee pre-image capture before page-cache
   commit.

## Decision

Attach eBPF kprobes to `vfs_write` and `security_file_permission`, with
fentry/fexit as the preferred 6.2+ BTF path. This places classification
directly at the VFS-to-page-cache boundary before any dirty page is
committed.

## Consequences

### Positive
- Sub-microsecond interception keeps p99 I/O overhead under 1.4%.
- Captures pre-image extents before encryption reaches the page cache.
- Works on stock Linux 6.2 / Ubuntu 22.04 kernels.

### Negative
- kprobes have higher per-event cost than fentry; must migrate to
  fentry/fexit once BTF is available.
- Requires root/CAP_BPF to load and attach.
- WSL2 explicitly excluded; target must be bare metal or VM.

## Revisit When

Migrate kprobes to fentry/fexit once BTF-enabled kernels are the
deployment baseline, or if a tracepoint exposing the page-cache boundary
becomes available.
